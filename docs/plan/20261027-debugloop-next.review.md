### A. 设计原则
- ✅ 通过：单一职责、开闭（`--mode` 扩参不改入口，白名单形态不变）、关注点分离、KISS（`cmp -s` 替 `md5sum` 去掉跨平台差异）
- **[P2·真实缺陷] A-1 常量「单一来源」名不副实**：plan:107 写「统一在 `settle.sh` 定义 `MIN_DUMP_BYTES=1024`，`findtap.sh` 复用同名变量但**各自定义**」——"统一"与"各自定义"自相矛盾，正是它自己要防的漂移。依据：plan:107 vs `android/_common.sh:1-2`（Android 公共段，settle/findtap/ui/tap 均已 source）。建议：常量 + 判定函数（`_ui_has_semantics()`）下沉 `_common.sh`；G12 增「两处口径同源」源码级断言（test_bg 组 13.8/14.24 是同类先例）。
- **[P2·真实缺陷] A-2 快速失败判据未限定在 `ui.sh` rc=0 分支**：plan:44/63 只写"首次 `ui.sh` 后读 size"。而 `ui.sh` 在 dump/pull 失败时 exit 1 **且不清理旧文件**（ui.sh:21-25,27-30），`$LOG_DIR/ui.xml` 是**上一轮残留**；现 findtap 对此有重试分支（findtap.sh:83-89）。触发：动画页 dump 超时 ⇒ 残留小文件 ⇒ 报「语义树无内容」，把「dump 失败」误诊为「页面无语义」，且抢掉原重试机会。建议：判据放 `else`（rc=0）分支且仅首轮判；口径对齐 `tap.sh:33-40`「先捕获 UI_RC」。
- **[P3·加固建议] A-3 阈值语义应随判据一起抽象**：size 是「dump 完整性」下限，不是「有无语义内容」的度量，两者被 plan 合成了一个 1024（见 B-1）。建议拆 `MIN_DUMP_BYTES`（完整性）+ `SEMANTIC_NODES_MIN`（内容性）两个常量。

### B. 可行性
- ✅ 通过：bash 3.2 兼容；`cmp`/`wc -c`/`grep -o` macOS 可用；不新增依赖、不改 `bg.sh`/`test_bg.sh` 契约；`$LOG_DIR/ui.xml` 与 appId 注入口径经核实成立；静态组递归 `find scripts -name '*.sh'` ⇒ plan:88「语法由静态组自动覆盖」正确
- **[P1·真实缺陷] B-1 `size ≥ 1024` 不能可靠识别「Flutter 空树」，反而可能双向失准**
  - 证据：plan:56/107 的「空树数百 B / 正常页数十 KB」无实测出处；`SKILL.md:292` 记录本仓唯一实测空树 = **1099 B > 1024**；`ui.sh:2-8` 对「清单为空」的定义是**没有带 text/desc 的节点**，与文件体积无因果
  - 触发：① Flutter 未开 semantics 时 dump 是骨架 XML（每节点 ~200–300 B），常落在 1–3 KB ⇒ 两帧相同且 ≥1024 ⇒ **仍秒判静止**（目标缺陷未消除）；② 原生极简页 dump ≈1 KB ⇒ **误判无内容并永久切 screen**
  - 建议判据（采纳）：用**非空 text/content-desc 节点数**（与 `ui.sh:51-53` 同口径），=0 ⇒ 无语义内容 ⇒ 切 screen；size 仅作完整性下限（如 <256 B 视为 dump 不完整）
  - 已否决备选：「直接默认 screen」——像素比对引入黑屏/息屏假阳性且每帧 0.5–1 s
- **[P1·真实缺陷] B-2 采样失败与「内容为空」未分态 ⇒ 假阳性换路径复活**：plan:53/57 让 `_sample_ui` 失败打印 `0`，切换条件 `size < 1024` ⇒ `0` 也满足。现实现的失败是**空串**并当「未静止」重试（settle.sh:34），语义区别于「有内容但相同」。触发：动画中 `could not get idle state` ⇒ 连续失败 ⇒ auto 永久切 screen ⇒ 若 FLAG_SECURE/息屏 ⇒ 两帧恒等 ⇒ rc=0「已静止」。建议：三态分离（失败→重试、连续 K 次才降级；成功无内容→切 screen；成功有内容→比对）；screen 独立阈值；rc=0 输出注明「判据=整屏像素」+ 两帧字节数
- **[P1·真实缺陷] B-3 G12 在现 adb 桩下不可通过**：`test_common.sh:54` `exec-out` 固定输出 `\211PNG…FAKEPNGBYTES` ≈20 B；按 plan:56「cmp 相同且 size≥1024 ⇒ 静止」，plan:88 的「`--mode screen`→rc=0」「`--mode auto`→切 screen 且 rc=0」**必红**。若为过断言把 size 门只用于 ui 采样，则 screen 退化为「两个 0 字节文件 cmp 相等即静止」，且 plan:88 **缺「空截图不误判静止」负控**。已核可过：`--mode ui→rc=3`、`findtap 小 ui.xml→rc=1` 用现桩可行。建议：扩桩（`exec-out` 输出 ≥ 阈值填充）或**新建第二套桩**（复用 `test_bg.sh:647,766` 的 `AB3_UI_XML` + `PATH=tools` 形态，可构造「语义为空但体积 1.5 KB」的真实反例）；补负控；若落 test_bg 需改写 §7「215 项不变」口径
- **[P1·真实缺陷] B-4 rc=1 的降级提示与 auto 切换自相矛盾**：plan:58 让 screen 超时提示「改用 `--mode ui`」，但走到 screen 的原因正是 ui 判「无内容」，改 ui 必得 rc=3。放大机制有仓内依据：`SKILL.md:38`「脚本的 💡 提示优先于自行重规划」⇒ 模型会照做 ⇒ rc=1→rc=3→auto 死循环。建议：提示按「是否发生过 auto→screen」分支——已切换过时给 `Maestro assert.sh` 轮询 / `shot.sh` 双帧 / `logwatch.sh <签名>`；仅 ui 采样有内容时才建议 `--mode ui`
- **[P2·加固建议] B-5 screen 模式成本上升未回灌默认值**：`screencap` 0.5–1 s/帧，但 `--timeout 8` 沿用（plan:52）⇒ 切换后 8 s 只够 2–3 帧。建议：切换时打印「每帧约 X s，必要时 `--timeout ≥ 15`」
